## 0. 今回確定した3つの前提

| # | 論点 | 確定内容 |
| --- | --- | --- |
| 1 | MAIN × SUBの扱い | PDVer.1は **MAIN × GOAL の15冊固定**。SUB4パターンは併記しない。個別性はWeb結果画面＋公式LINE初回返信で補完する。PDF本体は「あなたのSUB TYPEは診断結果画面で確認してください」という案内のみ。 |
| 2 | カラー | Webと同一ブランド方針。タイプ別のPurple/Green/Orangeは**使わない**。BLACK/NAVY/WHITE/OFF WHITE/TURQUOISE/ACCENT BLUEの8色のみで統一。タイプ差はアイコン・モチーフ・レイアウト・ラベル・TURQUOISE/NAVYの使い方で表現。 |

この3点にもとづき、以下STEP A〜Dを設計する。

**上記1の考え方を、スコア表示にも同様に適用した**（新たな判断ではなく1の延長）。AI活用スコア（5軸）もSUBと同じく個人ごとに変わる数値であり、PDF内に固定の数値やレーダー形状を印字できない。よってP.04は「空白レーダーチャート＋書き込み式」とし、Web結果画面の数値を転記してもらう設計にした。この点は次回レビュー時に問題なければそのまま、違和感があれば代替案（例：軸の意味の説明のみに留め数値は扱わない）を検討する。

## STEP D｜コンテンツ管理方式の提案

### 結論：**TypeScript（既存`data/`と同じ形式）を推奨**

### 理由

| 条件 | Markdown | JSON | TypeScript（推奨） |
| --- | --- | --- | --- |
| Webの既存データを再利用 | 参照不可（コピペになる） | 参照不可（コピペになる） | `import` で `data/resultTypes.ts` 等を直接参照でき、**同じ文章を複数箇所に書かない** |
| 15冊展開のしやすさ | ルートごとにファイルが増え、共通部分の再利用が手動 | `resultCombinations.ts` と同じ「キー付きオブジェクト」構造にできるが型保証なし | `resultCombinations.ts` と同じ形（routeId／P-ID／T-IDをキーにしたオブジェクト）にでき、既存の設計原則（データとUIを分離する `08`§10）と一貫する |
| 将来のPDF自動生成 | 都度パースが必要 | パース不要だが型なしでミスに気づきにくい | そのままNode/PDF生成スクリプトから直接importできる。`npm run typecheck` の対象にもできる |
| MOMOKAさんによる内容レビュー | ◎ 読み書きしやすい | △ 構造が見えにくい | △ コードに見えるため単体では読みにくい |

### 推奨フロー

```
1. 内容の設計・執筆・レビューは Markdown（このドラフトのような形式）で行う
   ↓ MOMOKAさんが読んで確認・修正しやすい
2. 内容が確定したら、既存 data/ と同じ規約で TypeScript データへ転記する
   ↓ 型チェックの対象になり、Web側データを import で再利用できる
3. PDF制作（Ver.1はCanva手動、将来は自動生成）はこのTypeScriptデータを参照する
```

### 想定するファイル構成（提案・未作成）

```
data/pdf/
├── roadmapDetails.ts   # routeIdごとのDay1-7詳細（今回のSTEP B相当）。将来15ルート分
├── prompts.ts          # P-IDをキーにした共通プロンプト集（全冊で使い回す）
├── tools.ts             # T-IDをキーにした共通ツール情報
└── common.ts            # 早見表・チェックリスト・進捗シート・表紙文言・免責文など全冊共通の文言
```

- `roadmapDetails.ts` の各Dayは、可能な範囲で `resultTypes.ts` の `learningSteps` / `keywords` 等を参照し、重複執筆を避ける。
- `prompts.ts` / `tools.ts` は最初から「全ルート共通の1つのマップ」として設計し、creator_side はそのうち関連するIDだけを参照する（今回のC-2で設計した考え方どおり）。
- Web側の `docs/00_`〜`09_` および `data/` 既存ファイルは**一切変更しない**（HANDOFF §14の禁止事項どおり）。

この構成の実際のファイル作成・コーディングは、内容がすべて確定してから着手する（今回はまだ行っていない）。
