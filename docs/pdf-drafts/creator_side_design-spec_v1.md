## 0. デザインコンセプト｜5つのキーワードの両立方法

MOMOKAブランドが求める「シンプル／上品・高級感／AIらしさ／少しポップ／親しみやすさ」は、一見相反する要素を含む。本書では、**役割を分けて共存させる**方針で解決する。

| キーワード | どう実現するか |
| --- | --- |
| シンプル・上品・高級感 | 色数を絞り（後述のブランドカラー8色のみ）、装飾を足さず、**余白・文字階層・1pxの罫線**で質を出す（Web版と同じ原則）。カードに影（ドロップシャドウ）はつけない |
| AIらしさ | 全ページに広げず、**プロンプト本文（PROMPT欄）だけにモノスペースフォント**を使うことで「これはAIに渡す入力である」という認識を作る。装飾的なドットグリッド・幾何学ラインは表紙など限られた箇所のみに使用 |
| 少しポップ・親しみやすさ | カード・チップの角を丸める、TURQUOISEを要所のアクセントとして使う、DAY番号やチェックボックスにやわらかい丸みを持たせる。**加えてMOMOKAオリジナルキャラクターを案内役として要所に配置する**（§4-8）。ネオン・原色多用はしない |

**やらないこと**（`06_pdf-spec.md`§11, §71と同じ）：派手なネオン、サイバー感過剰、占い感、テンプレート感の強いデザイン、タイプ別の虹色分け（紫・緑・オレンジ等）、カードへのドロップシャドウ多用。

## 0-1. ページサイズの変更｜A4縦 → スマホ縦型（9:16）

### 結論

**ページサイズを、A4縦（210×297mm）から「1080×1920px（9:16・スマホ縦型）」へ変更する。**

### 比較検討

| 観点 | A4縦（210×297mm） | スマホ縦型（1080×1920px・9:16） |
| --- | --- | --- |
| スマホでの表示 | PDFビューアで「幅に合わせる」表示にすると、A4の縦横比（約1:1.41）とスマホ画面（約1:2前後）が合わないため、上下に余白が残るか、拡大操作が前提になる。**本文12ptは、A4ページをスマホ幅に合わせて縮小すると実効約8px相当まで縮小する**（210mm≈595pt幅のページを360〜390px幅の画面に収めた場合の概算） | ページの縦横比が実際のスマホ画面に近く、画面いっぱいに表示される。拡大操作なしでそのまま読める。LINEやSNSストーリーズに近い自然な読み心地 |
| 印刷 | 標準規格。コンビニ・家庭用プリンタでそのまま印刷でき、書き込みワークブックとして紙運用しやすい | 標準規格外。印刷すると余白が大きく残るか特殊な用紙が必要。紙での書き込み運用には不向き（本書は「主にスマホで受け取り・実践する」用途のため、印刷対応は優先度を下げる） |
| PDFとしての配布 | 業界標準。すべてのビューアで違和感なく開ける | PDFとしての配布・LINEでのファイル共有・スマホのPDFビューアでの閲覧は問題なく可能（縦長ページとして扱われるだけ） |
| 1ページの情報量 | 面積が大きく、Day5や30日ロードマップのような情報量の多いページも1ページに収まりやすい | 面積はA4の約49%。同じ情報量だと窮屈になりやすく、**一部ページ（Day5・30日/90日ロードマップ・P-08等の情報密度が高いページ）はページ分割が必要になる可能性がある**（文章は削らずページを分ける、という既存原則で対応） |
| 主用途との整合 | 印刷・PC閲覧も含めた汎用フォーマット | **公式LINE配布・スマホ閲覧・実践**という本書の主用途に最も合致する |

### 判断理由

本書は「公式LINEから受け取り、スマートフォンで閲覧・実践する」ことが主要な利用シーンであり、印刷は主用途ではない。A4を前提にした場合の「スマホで縮小されると本文が読みにくくなる」という問題（既存デザインの本文サイズが実効8px相当まで縮む計算）は、可読性を最優先する本書の方針と相容れない。ページ面積が減ることによる情報密度の課題は、既存の「文章を削らずページ分割する」という原則（`creator_side_manuscript_v1.md`確定済み）で対応可能なため、**スマホ縦型を採用する**。

### ページサイズの技術仕様

- **アスペクト比**：9:16（縦長）
- **基準ピクセルサイズ**：1080×1920px
- **PDF書き出しの単位換算**：本書は印刷を前提としない画面閲覧用PDFのため、**1px＝1ptとして扱う**（DPI換算をしない。多くのデザインツール／PDF生成ツールの標準的な扱いに合わせる）。PDFページサイズは1080pt×1920ptとして書き出す
- **印刷する場合の扱い**：本仕様は印刷を前提としていないため、物理サイズ（mm/inch）は規定しない。読者が個人的に印刷したい場合は、大判プリンタでの縮小印刷、または分割印刷が必要になる旨をBOOK内に記載する必要はない（想定利用シーンではないため）

### ページ数への影響

文章・意味・ページ構成は`creator_side_manuscript_v1.md`を正本として変更しない。**39ページはあくまで基準であり、最終ページ数として固定しない**。ページ面積の縮小によって内容が窮屈になる場合は、**文字を小さくする・内容を削るのではなく、ページを分割することを優先する**。スマホ可読性のために必要であれば、39ページより増えて構わない。

特に以下は分割が必要になりやすいページとして事前に想定しておく：

- P.19 DAY5（STEP1〜4のワーク欄が多い）
- P.23／P.24 30日／90日ロードマップ（サブ項目が多い）
- P.31 P-08プロンプトカード（本編中最長）
- P.22 DAY7振り返り（記入欄5つ）

実際に分割するかどうか、最終的に何ページになるかはCodexでの制作時に判断し、変更が発生した場合は必ず報告する（`creator_side_manuscript_v1.md`の内容そのものは変更しない）。

### 1-2. 比率ルール（Web版と同じ）

- **土台80〜90%**：BLACK / NAVY / WHITE / OFF WHITE
- **アクセント10〜20%**：TURQUOISE / TURQUOISE LIGHT / ACCENT BLUE
- タイプ別（creator/producer等）に紫・緑・オレンジなどの固有色は**使わない**。タイプの違いはアイコン・モチーフ・レイアウトで表現する（既に本書では単一MAIN TYPEなので該当箇所なし）

### 1-3. 用途別カラーマッピング（Codexが迷わないための明示ルール）

| 要素 | 色 |
| --- | --- |
| 本文テキスト | NAVY（見出し）／BLACK 80%相当（本文）※純黒ではなくNAVY寄りのダークで統一感を出す |
| 見出し（H1/H2） | NAVY |
| eyebrow（小さな英字ラベル、例："WHY" "DAY NUMBER"） | TURQUOISE（**ただし背景がNAVY/BLACKなど暗い場合のみ**。白背景では下記1-5のコントラスト注意を参照） |
| 罫線・区切り線 | BORDER（`#DBE2EA`）の1pt線 |
| カード背景 | WHITE または TINT（`#F4F7FB`） |
| カード枠線 | BORDER 1pt |
| 強調バッジ・タグ塗り（例：SUPPORT PROMPT参照タグ） | ACCENT BLUE塗り＋WHITE文字 |
| チェックボックス（未チェック） | BORDER色の1.5pt枠線、塗りなし |
| チェックボックス（チェック済み想定の視覚見本） | TURQUOISE塗り |
| ロードマップの接続線・ノード | TURQUOISE |
| プロンプトカードの左アクセントバー | TURQUOISE |

### 1-4. ダークページの運用ルール

Web版の結果画面は複数セクションでダーク背景（NAVY/BLACK）を使い分けているが、**PDFは印刷して使う人も想定する**（`06_pdf-spec.md`§38）ため、ダーク背景ページは以下の**2ページのみに限定**する。

| ページ | 背景 | 理由 |
| --- | --- | --- |
| P.01 表紙 | NAVY | 最初の印象・保存性・スクショ耐性を最優先するため、唯一「濃い印刷コストを払ってでも」ダークにする価値があるページ |
| P.03 診断ルート | NAVY | BOOK全体で「ここから始まる」という宣言の重みを出すため。表紙の直後でダークが連続するが、あえて連続させることで導入の一体感を作る |

**それ以外の全ページはWHITE／OFF WHITE背景**（印刷コスト・視認性・スマホでの見やすさを優先）。P.14（TODAY MISSION）はP.03と同じ「ステートメント型」だが、Day1直前の「さあ始めよう」という軽やかさを出すためあえて**白背景**にし、P.03の重厚さと差別化する。

### 1-5. コントラストに関する注意（Web版の既知課題を踏襲）

`docs/HANDOFF.md`§15で、Web版の「ターコイズの英字ラベル（白背景）」がコントラスト比1.77（基準4.5未満）という既知の課題が報告されている。PDFでも同じ配色を使うため、**同じ問題を再現しないよう明示的にルール化する**。

- **TURQUOISEをテキスト色として使うのは、NAVYまたはBLACK背景の上のみ**（表紙・P.03）
- 白／オフホワイト背景でTURQUOISEを使う場合は、**文字色ではなく「線」「アイコンの塗り」「バッジの背景（文字はWHITE）」としてのみ**使用する
- 白背景でのeyebrowラベルは、TURQUOISEではなく**NAVY（または罫線＋NAVYの太字small caps）**を用いる

## 2. タイポグラフィ

### 2-1. フォント指定

| 用途 | フォント |
| --- | --- |
| 日本語（本文・見出し） | Noto Sans JP |
| 英字・数字（見出し・ラベル・DAY番号等） | Inter |
| **プロンプト本文（PROMPT欄のみ）** | モノスペース体（JetBrains Mono、なければ system-ui monospace） |

プロンプト欄だけモノスペースにする理由：「これはコピペしてAIに渡す入力そのものである」という視覚的な合図にするため。他の場所では使わない（AIらしさを局所化し、本全体がサイバーっぽくなるのを防ぐ）。

### 2-2. サイズ階層（1080×1920pxキャンバス基準）

ページ幅1080pxが実際のスマホ画面幅とほぼ一致する前提で、拡大操作なしに読める大きさを直接指定する（`06_pdf-spec.md`§68のpt値をmm換算で引き継ぐのではなく、モバイル表示での可読性を起点に再設計した）。

| レベル | サイズ | ウェイト | 用途 |
| --- | --- | --- | --- |
| Display（表紙のみ） | 100px | Bold | 表紙のBOOKタイトル |
| H1 | 88px | Bold | ページ見出し（MAIN TYPE名、DAY テーマ等） |
| H2 | 64px | Semibold | セクション見出し |
| H3 | 52px | Semibold | カード見出し・プロンプトタイトル |
| Body | 48px | Regular | 本文（スマホ画面で拡大なしに読める大きさを優先） |
| Small / Caption | 40px | Regular | 補足文・出典・免責 |
| Eyebrow | 36px | Semibold・letter-spacing広め | 小さな英字ラベル |
| プロンプト本文（モノスペース） | 44px | Regular | PROMPT欄のみ |

### 2-3. 行間

- 本文：1.7倍
- 見出し：1.3倍
- プロンプト本文（モノスペース）：1.6倍

## 4. コンポーネント仕様

### 4-1. カード（強み／注意ポイント／ツール紹介で使用）

- 背景：WHITE
- 枠線：BORDER 2px、角丸16px
- 内側パディング：48px
- 見出し（H3）＋本文（Body）の縦積み構造
- 番号・アイコンバッジ：NAVY円形（直径56px）の中にWHITEの数字またはLucideアイコン
- **影（ドロップシャドウ）は使用しない**（枠線のみで質感を出す＝上品さの担保）
- 枚数が3〜6枚の可変グリッドに対応：**スマホ縦型では横に並べず、原則1列縦積み**とする（1080px幅に2列グリッドを組むと1カード幅が狭くなりすぎるため。A4のような2列グリッドは採用しない）

### 4-2. タグ／チップ（P.10, P.13で使用）

- 背景：TINT（`#F4F7FB`）
- 文字色：NAVY
- 枠線：BORDER 2px
- 角丸：999px（ピル形状）
- パディング：横32px／縦16px
- 折り返しレイアウト（横に並べて、入りきらない分は次の行へ）

### 4-3. 図解・ロードマップ（P.04, P.12, P.23, P.24で使用）

- **シンプル型**（P.04, P.12）：縦一直線の接続線（TURQUOISE、太さ4px）＋各ステップに円形ノード（直径24px、TURQUOISE塗り）。ステップ名は右側にH3サイズで配置
- **詳細型**（P.23, P.24）：シンプル型と同じ接続線＋ノードだが、各ステップの下に本文・SUPPORT PROMPTタグ・具体例リストなど複数行のサブ項目を持てる可変ブロック構造。ステップ間の余白は64px以上確保する。**WEEK2のように情報量が多いステップは、1ページに収まらない場合、無理に詰め込まずページを分割する**（§0-1参照）
- **90日ロードマップの「育てる」サイクル部分（DAY90）のみ**、直線ではなく**円環（ループ）の矢印図**にする。「実践→反応を見る→改善→再提案／再発信」が繰り返すことを視覚的に伝えるため

### 4-4. ワーク欄（記入欄・チェックボックス）

- 記入欄（自由記述用の線）：BORDER色、太さ2px、下線のみ（罫線ノート風）。1行の高さは36px
- チェックボックス：一辺28px、角丸8px、枠線BORDER 3px（塗りなしがデフォルト状態。塗りつぶし例を見せる場合のみTURQUOISE塗り＋WHITEチェックマーク）
- STEP形式（Day5等）：番号バッジ（NAVY円形・直径40px・白数字）＋ラベル＋説明文の横並び行を縦に積む

### 4-5. プロンプトカード（P-01〜P-20、最重要コンポーネント）

```
┌─────────────────────────────┐
│ [CATEGORY バッジ]  P-08｜価格設定・提案文   │ ← H3見出し + カテゴリバッジ（NAVY文字、TINT背景、色分けはしない）
│                                             │
│ WHEN（eyebrow・NAVY）                        │
│ 作品に値段をつけ、相手への提案文を書くとき   │ ← Body
│                                             │
│ ┃PROMPT（eyebrow・NAVY）                     │
│ ┃┌───────────────────────┐        │
│ ┃│あなたは価格設定・提案文作成の… │        │ ← モノスペース体、TINT背景、
│ ┃│【目的】…                      │        │   左に8px幅のTURQUOISEアクセントバー
│ ┃│【私の情報】…                  │        │   内部の【】構造もそのまま
│ ┃└───────────────────────┘        │   （コピペそのままの見た目にする）
│                                             │
│ CUSTOM（eyebrow・NAVY、鉛筆アイコン）        │
│ [ここに書く]6箇所を実際の制作内容に…        │ ← Body、背景なし
│                                             │
│ INPUT EXAMPLE（eyebrow・NAVY、吹き出しアイコン）│
│ ┌───────────────────────┐          │
│ │作品の種類：LP制作／制作時間：約10時間… │  │ ← Body（モノスペースではない通常フォント）、
│ └───────────────────────┘          │   TURQUOISE LIGHT 15%程度の薄い塗り背景
└─────────────────────────────┘
```

- カード外枠：BORDER 2px、角丸24px、パディング56px
- カテゴリバッジは**色分けしない**（制作＝赤、副業＝青のような虹色化はブランドルール違反。すべてTINT背景＋NAVY文字の同一デザイン、文字だけで category を示す）
- PROMPT欄とINPUT EXAMPLE欄は**背景の濃淡と書体で明確に区別**する（PROMPT＝モノスペース＋TINT、INPUT EXAMPLE＝通常書体＋TURQUOISE LIGHT薄塗り）。読者が「どちらをコピペすべきか」に迷わないようにするための最重要ルール
- スマホ縦型は1ページの面積が小さいため、**1ページ1本を基本**とする（A4基準だった「1ページ2本」からの変更。P-08のように長いプロンプトはこの1本でも縦に長くなることを許容し、無理に収めない）

### 4-6. ページ番号・ヘッダー／フッター

- フッター：ページ下部中央に「01」のようなゼロ埋め2桁のページ番号。BORDER色の罫線をページ番号の上に引き、本文と区切る
- ヘッダー（ランニングヘッド）：ページ上部左に、現在地が分かる小さなラベル（例：DAY5ページなら「7-DAY CHALLENGE」、プロンプト集なら「PROMPT COLLECTION」）。36px、NAVY 60%、letter-spacing広め
- 表紙・最後のメッセージページにはヘッダー／フッターを付けない（没入感を優先）

### 4-7. アイコン・装飾

- アイコンセットはWeb版と統一し**Lucide（アウトラインスタイル）**を使用。塗りつぶしアイコンは使わない
- 標準ストローク幅：3px
- アイコン色：NAVY（基本）／WHITE（NAVY背景の上）／TURQUOISE（アクセントとして使う場合のみ、かつ背景要件は1-5の注意に従う）
- 装飾は「罫線」「小さな円・ドット」「幾何学的なコーナーマーク」に限定し、**表紙とP.03のみ**で使用可（他ページはアイコン以外の装飾を足さない）

### 4-8. MOMOKAオリジナルキャラクター（案内役）

**位置づけ**：単なる装飾ではなく、読者に寄り添う案内役（ナビゲーター）として使用する。ブランドの「少しポップ・親しみやすさ」を担う主な要素の1つ。**画像そのものは今回未確定**（Codexでの実制作開始時に別途用意・指定する）。ここでは配置基準・ポーズ選択ルール・配置スペースを定義する。

**配置ページ数を先に固定しない**：何ページに配置するかを本仕様書側であらかじめ決めない。39ページ全体を実際に組版した結果を見て、以下の「配置基準」に照らして**ページの内容に意味を持つ箇所だけ**に配置する。基準を満たさないページには無理に配置しない。目安として全39ページの一部（装飾目的で機械的に増やさない範囲）にとどめる。

**配置基準（該当する場合のみ配置）**：

- 表紙
- セクションの切り替わり（BOOK内の話題の転換点）
- 重要ポイント（特に強く伝えたい一文がある箇所）
- 注意事項（気をつけてほしいことを伝える箇所）
- 行動を促すページ（「やってみよう」に相当する行動喚起の箇所）
- 達成／完了ページ（7日間・各Dayの完了など、読者の頑張りをねぎらう箇所）

カード・タグが多く視覚要素がすでに密なページや、記入欄中心でスペースを最優先すべきページには、上記に該当しない限り配置しない。**情報理解・視線誘導に意味を持つかどうか**を基準に、ページごとに判断する。

**ポーズ素材（10種類）と選び方**：

MOMOKAキャラクターは10種類程度のポーズ素材を用意する（画像は別途提供）。**ページの内容に応じて意味のあるポーズを選ぶ**。装飾として機械的に同じポーズを繰り返し置かない。

| ポーズ | 主に使う場面 |
| --- | --- |
| 基本案内 | 表紙、セクションの切り替わり（章の始まりを紹介する） |
| PC作業 | 制作・作業を表すページ（例：DAY5などの制作場面） |
| 指差し | 注目してほしい箇所、SUPPORT PROMPTなど参照先を示す場面 |
| ひらめき | 重要ポイント、気づきを促したい場面 |
| 考える | 注意事項、慎重に受け止めてほしい場面 |
| 応援 | 行動を促すページ、挑戦の後押しをしたい場面 |
| OK | 完了条件（DONE CONDITION）、行動を肯定したい場面 |
| スマホ | LINE REPORTなど、スマホでの操作・報告を促す場面 |
| 説明・プレゼン | 概念やしくみを説明するページ（例：タイプ紹介、ロードマップ） |
| 達成・喜び | DAY7・7日間振り返りなど、達成・完了をねぎらう場面 |

**配置スペースの設計**：

- 標準サイズ：キャラクターの基本表示幅は160〜200px相当（本文を邪魔しない、ページの主役にならないサイズ）
- 標準配置位置：ページ下部の右または左の余白（コンテンツ幅920pxの外側、セーフマージン内）
- 表紙のみ特別扱い：中央下部にやや大きめ（240〜280px相当）に配置してよい。ブランドの顔としての存在感を出すため
- 余白を広く使うステートメント型ページ（例：P.14）：キャラクターもやや大きめ（200〜240px）に配置可。ただし本文の文字より目立たせない。P.03（診断ルート）はダーク・重厚さを優先し配置しない
- セリフ（吹き出し）の使用：重要ポイント・注意事項・行動喚起・達成の場面では、キャラクターに短い一言セリフ（1行以内、例：「ここ大事！」「まずはやってみよう」「よくできました！」）を吹き出しで添えてよい。**セリフは本文の意味を変えない・新しい情報を追加しない**（あくまで感情の後押し、要約や言い換えはしない）

**禁止事項**：

- ページの主役級の大きさで配置しない（本文・見出しより視覚的に目立たせない）
- 1ページに複数キャラクター（ポーズ違い含む）を登場させない
- 配置基準に当てはまらないページへ、装飾目的で機械的に配置しない
- ページの内容と無関係なポーズを選ばない（例：注意事項のページに「達成・喜び」を使う、等）
- セリフに本文と矛盾する内容・新しい主張を持たせない
- タイプ別に色や表情を変えて“紫のクリエイターキャラ”のような虹色分けをしない（`06`§11「占い感」回避、ブランドカラールールとも整合）

## 5. スマホでPDFを見たときの読みやすさ（数値ルール）

ページサイズをスマホ縦型（1080×1920px）にしたことで、「A4を縮小して読む」問題は構造的に解消されている。PDFビューアの「幅に合わせる」表示で、ページ幅1080pxがほぼそのままスマホの画面幅に収まるため、拡大操作なしで読める。本章は、その前提の上でなお守るべき数値ルール。

| 項目 | ルール |
| --- | --- |
| 本文最小サイズ | 48px（§2-2のBody以下を本文に使わない） |
| ラベル最小サイズ | 36px（eyebrowが下限） |
| 列数 | 本文は常に1カラム。カードグリッドも横に並べず1列縦積み（§4-1）。表（P.25等）も列数は3列まで、それ以上は縦積みのカード形式にする |
| マージン | 全ページ共通で左右80px確保（端でのクロップ・機種ごとの画面比率の違いに耐えるため） |
| チェックボックス・記入欄のタップ／視認サイズ | 最小28px四方（§3参照） |
| 図解の文字 | ロードマップ内の文字は40px以上を維持する |
| コントラスト | 本文はNAVY on WHITE/OFF WHITEを基本とし、WCAG AA（4.5:1）を満たす組み合わせのみ使用。§1-5のTURQUOISE運用ルールを厳守 |
| 画面比率の違いへの対応 | 9:16は実際のスマホ画面比率（9:19〜9:20台の機種もある）より横長のため、縦にわずかな余白（レターボックス）が出る機種がある。これは想定内であり、崩れではない。左右がクロップされる方向のズレは起きない設計にする |
