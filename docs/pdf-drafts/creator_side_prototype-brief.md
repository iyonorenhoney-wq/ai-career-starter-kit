### 5-5. 実践プロンプト P-08｜価格設定・提案文

出典：`docs/pdf-drafts/creator_side_v5_final.md`（P-08本文＋A-3のINPUT EXAMPLE修正版）

```
CATEGORY：副業
P-08｜価格設定・提案文

WHEN
作品に値段をつけ、相手への提案文を書くとき

PROMPT
あなたは価格設定・提案文作成のアシスタントです。

【目的】
私が作品に価格をつけ、相手に送る提案文を作る手助けをしてください。
ただし、具体的な金額の相場を断定しないでください。

【私の情報】
作品の種類：[ここに書く]
制作にかかった時間の目安：[ここに書く]
難易度（自分の感覚でよい）：[ここに書く]
修正対応の回数（何回まで対応するか）：[ここに書く]
納品物の形式（データ形式・提供方法）：[ここに書く]
利用範囲（個人利用のみ／商用利用可など）：[ここに書く]

【前提】
・あなたが持っている価格相場の情報は古い、または不確実な場合があります
・具体的な金額を断定したり、「相場は○○円です」と言い切ったりしないでください
・分からない・確認できない情報は「確認できません」と明示してください

【判断基準】
価格に影響しうる一般的な考え方（断定しない範囲で）：
・制作時間が長いほど、難易度が高いほど、修正対応が多いほど、価格を上げる要因になりやすい
・商用利用や納品物の範囲が広いほど、価格を上げる要因になりやすい
この考え方はあくまで一般論であり、実際の金額は本人が判断してください。

【進め方】
1. 上の入力情報のうち、価格を考えるために必要な項目が揃っているか確認してください。欠けている項目があれば、価格の話をする前に質問してください
2. 揃っている情報から、価格を考える際に整理しておくべきポイントを挙げてください（金額は断定しない）
3. 相場感について触れる場合は、必ず「これは参考情報であり、断定はできません」と明記した上で、幅を持たせた考え方を示してください
4. 相手に送る提案文の下書きを作成してください。価格欄は私が自分で数字を入れられるよう空欄にしてください

【出力してほしい内容】
①価格を考える際に整理すべきポイント
②相場についてのコメント（断定しないことを明記）
③提案文の下書き（価格部分は空欄）

【出力形式】
①②③の見出しに分けて出力してください。

【情報が不足している場合】
制作時間・難易度・修正回数・納品物・利用範囲のいずれかが空欄の場合、価格の話に進まず、先にその項目を質問してください。

CUSTOM
[ここに書く]6箇所を実際の制作内容に書き換えて使用

INPUT EXAMPLE
作品の種類：LP制作／制作時間：約10時間／難易度：中（初めてのジャンル）
修正対応：2回まで／納品物：完成データ一式＋公開URL／利用範囲：商用利用可
```

## 8. スマホPDF閲覧を前提とした可読性

**攻略BOOKは公式LINEから受け取り、スマートフォンで閲覧するユーザーが主要な利用シーンである。** A4のPDFとして作るが、スマホでの可読性を最優先すること。

- 本文最小12pt、eyebrowラベル最小9pt（`design-spec_v1.md`§5のルールを厳守）
- 横に並べすぎない。列数は最大3列、それ以上は縦積みのカード形式にする
- チェックボックス・記入欄は最小14pt四方を確保する
- **PDFは中身が固定レイアウトのA4ページであり、スマホで見てもレイアウトが組み替わる（レスポンシブ）わけではない。** そのため確認方法は「A4ページをスマホの表示幅相当（約380px）に縮小した状態で、文字・図解が読めるか」であり、「モバイル用に別レイアウトを作る」ことではない
- 各HTMLページに、**実寸（A4）表示とスマホ幅縮小表示（約380px幅相当）を切り替えられるトグルボタン**を実装すること（`transform: scale()`を使い、同じ要素を縮小表示する形。別レイアウトを作らない）

- 5ページすべてが同じ`tokens.css`／`components.css`を参照すること（ページごとに独自の色・フォントサイズを定義しない）
- ヘッダー／フッター／ページ番号のマークアップ構造を5ページで共通化する（コピー＆微調整ではなく、共通パーツとして扱う）

- 5ページを並べて見たときに「別々の資料をつなぎ合わせた」印象にならないよう、余白の取り方・見出しの大きさの相対関係を統一する

## 14. 実装形式（この試作フェーズで採用する方式）

**スタンドアロンHTML＋CSS**で実装すること。Next.jsアプリのコンポーネント化・ルーティング追加は行わない。

**理由**：
- 攻略BOOKはWebアプリ（診断アプリ）とは別の成果物であり、既存の`app/`・`components/`・`data/`に一切触れずに独立して試作・確認できる必要がある
- A4固定レイアウトの印刷物であり、Reactの状態管理やルーティングは不要。素のHTML/CSSの方が要件に対して余計な抽象化がなく、レビューしやすい
- ブラウザで直接開いて確認でき、実寸表示とスマホ幅縮小表示の切り替えも軽量に実装できる
- 本制作（39ページ・残り14冊）でのPDF自動生成（例：ブラウザ印刷／Puppeteer等）にもそのまま発展させやすい
