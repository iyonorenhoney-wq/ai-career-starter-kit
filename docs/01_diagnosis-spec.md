# AIキャリアスターターキット｜Diagnosis Specification

## 1. ファイル概要

### ファイル名
`01_diagnosis-spec.md`

### 目的
AIキャリアスターターキット内で使用する、
**AI仕事診断の機能・画面・判定結果・ユーザー導線の仕様を定義する。**

このファイルでは、

- 診断の目的
- 診断全体フロー
- 画面構成
- 回答仕様
- 診断結果仕様
- MAIN / SUB / GOAL
- STYLE
- AI活用スコア
- 結果シェア
- スクリーンショット導線
- 公式LINEへの移動
- エラー・再診断
- 保存データ
- 実装時のルール

を定義する。

質問本文と採点点数の詳細は別ファイルで管理する。

関連ファイル：

- `00_product-overview.md`
- `02_scoring-system.md`
- `03_question-bank.md`
- `04_result-types.md`


---

# 2. 診断名称

## 正式名称候補

### メイン名称
**AI仕事診断**

### 結果コンテンツ名称
**AI仕事診断書**

診断開始前は分かりやすさを優先して
「AI仕事診断」と表記する。

診断完了後は、

**あなたのAI仕事診断書**

として結果を提示する。


---

# 3. 診断のコンセプト

この診断は、

「AIに詳しいか」

「AIスキルが高いか」

を測定するテストではない。

目的は、

**その人がAIをどのように仕事へ活用すると、行動しやすく成果につなげやすいかを整理すること。**

診断結果から、

- AI活用タイプ
- サブタイプ
- 現在の目的
- 向いているAI活用
- 次に取るべき行動

を提示する。


---

# 4. 診断で判定するもの

診断では大きく2種類を判定する。


## A. AI活用タイプ

5タイプから判定する。

1. AIスマートワーカー
2. AIクリエイター
3. AIサポーター
4. AIプロデューサー
5. AIビルダー


## B. AI活用目的

3種類から判定する。

1. WORK
2. SIDE
3. BOTH

**全10問**

とする。

## 目的判定

# 8. 診断所要時間

目標：

**約2〜3分以内**

ユーザーが、

「ちょっとやってみよう」

と思える軽さを維持する。

長文入力は診断内では求めない。

基本は選択式。


---

# 9. 診断形式

全質問、

**単一選択式**

とする。


タイプ判定：

5択


目的判定：

3択

## サブコピー

10個の質問から、

# 11. 開始画面で表示しないもの

開始時点では、

- 5タイプの詳細
- 各回答とタイプの対応
- 採点ルール
- 15ルート
- 商品導線

は表示しない。

理由：

回答誘導を防ぐため。

# 12. 診断画面基本レイアウト

各質問ページには以下を表示する。


## 上部

進捗表示。

例：

```text
QUESTION 03 / 10
```

または

```text
3 / 10
```


## プログレスバー

進捗率を視覚表示する。


例：

Q1

10%


Q5

50%


Q10

100%


## 中央

質問文。


## 下部

回答選択肢。


## 最下部

必要に応じて、

「前の質問へ」

を表示。


---

# 13. 質問表示ルール

1画面につき1質問。

複数質問を同時表示しない。

理由：

- スマートフォンで回答しやすくする
- 診断体験を軽くする
- 回答への集中を高める
- スクリーンサイズによる崩れを防ぐ


---

# 14. 回答UI

回答はカード形式を基本とする。


例：

```text
┌────────────────────────────┐
│ 情報を整理して              │
│ 分かりやすくまとめる        │
└────────────────────────────┘
```

選択すると、

- 選択状態を表示
- 自動で次へ進む

または

- 「次へ」ボタンを有効化

のどちらか。


---

# 15. Ver.1の回答遷移

Ver.1では、

**回答カード選択 → 0.2〜0.4秒程度 → 自動で次の質問**

を第一候補とする。

ただし、

誤タップが多い場合は、

「次へ」ボタン方式へ変更可能とする。


---

# 16. 選択肢順序

タイプ判定Q1〜Q7では、

回答のタイプ対応がユーザーから分からないように、

**各質問で選択肢順を変える。**

例：

Q1

SP
CR
SW
BL
PR


Q2

CR
SP
SW
BL
PR


のように固定順を避ける。


---

# 17. ランダムシャッフルについて

Ver.1では、

**アクセスごとの完全ランダムシャッフルは必須としない。**

理由：

- テスト結果を比較しやすくする
- 不具合確認をしやすくする
- スクリーンショット検証をしやすくする

質問ごとにあらかじめ順番を変えた状態で固定する。

将来的に必要ならランダム化する。


---

# 18. 戻る機能

ユーザーは、

**1つ前の質問に戻れる。**

戻った場合、

以前の回答を表示する。

回答変更時は、

古いスコアを削除し、

新しい回答のみ採点する。


---

# 19. リロード時

Ver.1では、

診断途中の回答をブラウザ内に一時保存する。


保存候補：

```text
localStorage
```

目的：

誤操作やリロードで最初からにならないようにする。

# 23. MAIN TYPE

5タイプの中で、

最も高いタイプスコアをMAINとする。

例：

```text
creator: 12
builder: 10
producer: 7
smart_worker: 5
supporter: 4
```

結果：

```text
MAIN = creator
```


---

# 24. SUB TYPE

2番目に高いタイプをSUBとする。

上記例：

```text
SUB = builder
```


---

# 25. サブタイプの役割

サブタイプは、

単なる2位表示ではなく、

**ユーザーの強みの組み合わせを説明するために使用する。**

例：

MAIN

AIクリエイター


SUB

AIビルダー


表示例：

**「作る力」と「仕組みに変える力」を持つハイブリッドタイプ。**


---

# 26. STYLE

タイプスコアの差から、

ユーザーのAI活用スタイルを表示する。


## 特化型

MAINが他タイプより明確に高い場合。


表示例：

```text
AIクリエイター特化型
```


## ハイブリッド型

MAINとSUBが近い場合。


表示例：

```text
AIクリエイター × AIビルダー
ハイブリッド型
```


## マルチAI活用型

上位3タイプが近い場合。


表示例：

```text
マルチAI活用型
```


具体的な閾値は、

`02_scoring-system.md`

で定義する。


---

# 27. GOAL

Q8〜Q10の回答から、

以下のいずれかを決定する。

- WORK
- SIDE
- BOTH


表示例：

```text
GOAL
副業・収益化
```

# 28. SECONDARY GOAL

Ver.1では、

内部データとして2位の目的も保持する。

ただし、

結果画面には必ずしも表示しない。


使用目的：

- PDF選定
- LINE返信
- 商品提案
- 将来のセグメント配信


例：

```text
Primary Goal:
WORK

Secondary Goal:
SIDE
```

# 29. AI活用スコア

生点をそのままユーザーに見せない。

表示用に、

0〜100程度のスコアへ変換する。


例：

```text
仕事効率化 62
制作 87
サポート 43
商品化 69
仕組み化 78
```


---

# 30. スコアの表現

使用する：

**AI活用スコア**

使用しない：

- 適性率
- 才能率
- 成功率
- 向いている確率


理由：

心理検査や科学的適性試験のような誤解を避ける。

# 33. シェア用結果カード

結果画面最上部に配置する。

スクリーンショットのみで、

結果概要が理解できるものとする。


表示内容：

- AI仕事診断書
- MAIN TYPE
- SUB TYPE
- GOAL
- STYLE
- 一言キャッチコピー
- MOMOKAまたはブランド表記


例：

```text
AI仕事診断書

MAIN
AI CREATOR

SUB
AI BUILDER

GOAL
副業・収益化

STYLE
CREATOR × BUILDER

「アイデアを形にし、
さらに仕組みに変えていくタイプ」
```


---

# 34. シェアカードの目的

1. ユーザーが保存したくなる
2. SNSに投稿したくなる
3. 他人が見て診断したくなる
4. 公式LINE送信に利用できる


---

# 35. シェアカードデザイン

重要条件：

- スマホ縦画面で綺麗に収まる
- スクリーンショットしやすい
- 情報を詰め込みすぎない
- タイプ名を大きくする
- MAIN / SUB / GOALが一目で分かる
- ブランド名を小さく表示する


---

# 36. 結果詳細

シェアカード下に、

診断結果の説明を表示する。


例：

## あなたはこんなタイプ

あなたは、
アイデアを頭の中だけで考えるより、

**実際に形にしながら理解を深めるタイプです。**

AIを質問相手としてだけ使うより、

「一緒に作る相棒」

として使うことで強みが出やすくなります。


---

# 37. MAIN TYPE詳細

表示項目：

- タイプ名
- キャッチコピー
- 基本説明
- 強み
- 注意ポイント
- 向いているAI活用


詳細本文は、

`04_result-types.md`

で管理する。


---

# 38. SUB TYPE詳細

SUB TYPEはMAINより簡潔に表示する。

表示項目：

- サブタイプ名
- MAINとの組み合わせ
- サブタイプが活きる場面


例：

```text
SUB TYPE

AI BUILDER

あなたは制作だけでなく、
「もっと効率よくできないか？」
と仕組みを考える傾向もあります。
```


---

# 39. MAIN × SUB説明

将来的には、

MAIN × SUBの組み合わせごとに文章を用意する。

5タイプから異なる2タイプを組み合わせるため、

主要パターンを段階的に追加する。


Ver.1では、

テンプレート方式でもよい。


例：

```text
あなたは「制作」を軸にしながら、
「仕組み化」の強みも持っています。

作るだけで終わらず、
作ったものをより便利な形へ発展させることで
強みを活かしやすいタイプです。
```

# 40. GOAL表示

現在ユーザーがAIを使って目指している方向として表示する。


例：


```text
まずAIを使って、
小さくても自分で収入を作る経験を目指すルートです。
```

# 45. 「今一番変えたいこと」

結果画面上では自由回答を求めない。

公式LINE上で本人から送ってもらう。


案内例：

```text
スクショと一緒に、

「今一番変えたいこと」

を一言送ってください。

例：
・仕事でAIを使えるようになりたい
・副業を始めたい
・Web制作を仕事にしたい
・商品を作りたい

長文じゃなくて大丈夫です。
```

# 46. 公式LINEボタン

CTA例：

**専用攻略本を受け取る**

ボタン押下：

公式LINEへ移動。


LINE URLは、

Ver.1公開前に設定する。


環境変数または設定ファイルで管理し、

コード内へ直接複数箇所記述しない。


例：

```text
NEXT_PUBLIC_LINE_URL
```


---

# 47. CTAを押しても診断結果は保持

公式LINEへ移動後に戻ってきても、

診断結果を確認できるようにする。

結果はlocalStorage等に保存する。


---

# 48. 診断結果ID

各診断結果に簡易IDを生成する。

例：

```text
AI-260808-X4K9
```

用途：

- 診断書感
- 将来的な自動化
- 問い合わせ時の識別
- 結果照合


Ver.1では完全なユーザー識別用途には使用しない。


---

# 49. 結果ID生成要件

個人情報を含めない。

使用しないもの：

- 氏名
- メールアドレス
- 電話番号
- LINE ID


候補：

```text
AI-
日付
+
ランダム英数字
```


---

# 50. ユーザー名

Ver.1の診断では、

名前入力は必須にしない。

理由：

- 診断開始ハードルを下げる
- 個人情報収集を最小限にする


将来的に、

「〇〇さん専用AI仕事診断書」

の表示を行いたい場合は、

任意入力として追加可能。


---

# 51. 再診断

結果画面に、

**もう一度診断する**

を表示する。


押下時：

確認モーダルを表示。


例：

```text
診断結果をリセットして
最初からやり直しますか？
```


選択肢：

- やり直す
- キャンセル


---

# 52. 再診断時の処理

「やり直す」を選択すると、

以下を削除。

- answers
- currentQuestion
- diagnosisResult

その後、

Q1へ戻る。

**スクリーンショットで共有できる設計**

を必須とする。

- Xシェア

- Instagram Stories
- 画像ダウンロード

を追加可能。

# 55. 結果画面のレスポンシブ

最重要：

**スマートフォン優先。**

理由：

SNS
↓
オープンチャット
↓
診断

という導線から、

スマホアクセスが多いことを想定する。

- iPhone
- Android
- iPad
- PC

# 57. PC表示

PCでも、

診断カード自体を横に広げすぎない。

最大幅を設定する。


診断自体は中央配置。

# 58. アクセシビリティ

最低限以下を守る。

- 文字サイズを小さくしすぎない
- 選択肢のタップ領域を広くする
- 色だけで選択状態を示さない
- キーボード操作を可能にする
- コントラストを確保する

- 洗練

- 信頼
- スマート

# 88. 最重要思想

この診断の目的は、

ユーザーをタイプ分けして楽しませるだけではない。


最終的に、

**「自分は次に何をしたらいいか分かった」**

という状態へ持っていく。

**実際に最初の行動を起こしてもらう。**

そのため、

診断結果はゴールではなく、

AIキャリアスターターキットの

**START地点**

として設計する。
